# AQAR (عقار) — Claude Code instructions

Map-based real estate website for Jordan and the Gulf (phase 1: Jordan only). Arabic-first (RTL) with English (LTR).
**Full specification: `docs/SPEC.md`** — read the relevant section before starting any task.

## Stack
- React 19 + React Router v7 (framework mode, SSR) + TypeScript (strict) + Vite + Tailwind CSS
- Express server hosting the React Router handler and REST API at `/api/v1`
- PostgreSQL 16 + PostGIS (Docker in dev), Knex for migrations and queries, Zod for validation
- MapLibre GL JS + OpenFreeMap vector tiles (`MAP_STYLE_URL_*` env), terra-draw for draw-to-search
- **All software free/open source; only hosting is paid.** No paid third-party services, APIs or libraries.
- Production: one Linux VPS — Node 24 LTS app, PostgreSQL 16 + PostGIS on the same host, Caddy for HTTPS, images on the VPS disk via the storage interface, nightly `pg_dump` + image backups (SPEC §0).

## Commands
Node 24 LTS (`>=24 <25`, see `.nvmrc`). Copy `.env.example` to `.env` first.
- `docker compose up -d` — start local PostGIS (dev only; production PostgreSQL + PostGIS runs on the VPS)
- `npm run dev` — Express + Vite dev server with SSR on `PORT` (default 3000); `/` → `/ar/jo/map`
- `npm run build` / `npm start` — production build (`build/`) and server (`NODE_ENV=production`)
- `npm run db:migrate` / `npm run db:rollback` / `npm run db:seed` — Knex via `tsx` (`knexfile.ts`)
- `npm run typecheck` — `react-router typegen` + `tsc --noEmit`
- `npm run lint` — ESLint (`eslint.config.ts`); custom rule `aqar/no-physical-direction` (`eslint-rules/`) fails on left/right Tailwind utilities in `app/` TS/TSX and CSS `@apply`; `css/prefer-logical-properties` covers left/right CSS properties
- `npm test` — Vitest (`*.test.ts` next to the code)

## Layout notes
- `server/index.ts` — entry: reads env and calls `createServer()` (`server/createServer.ts`): origin check (CSRF), `/api/v1` (`server/api`: rate limit → `authenticate` → routers), `/uploads` (dev only — Caddy serves it in production), then `authenticate` + the React Router handler, created there for both modes (dev: Vite's `virtual:react-router/server-build`; production: `build/server/index.js`) with `createGetLoadContext(services)` from `server/loadContext.ts`. `npm run dev` runs `tsx watch`, so the server restarts when server code changes (e.g. after `git pull`); route modules reload through Vite.
- `app/routes.ts` — route config: `/:lang` (layout, validates locale) → `login`, `register`, `:country/map` (validates against `ACTIVE_COUNTRIES` in `app/shared/countries.ts`); POST-only `/theme` and `/logout`.
- Auth (SPEC §13): `server/services/authService.ts` (register/login/rotation/logout), `tokenService.ts` (JWT, refresh tokens, `SESSION_POLICY`), `rateLimitService.ts`; middleware in `server/middleware/`. Loaders/actions get `context.session` and `context.services`; guard pages with `requireUser`/`requireRole` (`app/utils/auth.server.ts`); components use `useAuth()` (`{ id, name, role }` only).
- Map search (SPEC §5): search state schema `app/shared/schemas/mapSearch.ts` (URL ↔ loader ↔ API); server `server/services/searchService.ts` (points, cards), `areaService.ts` (levels, outlines, path), routes in `server/api/search.ts`; page `app/routes/map.tsx` (SSR first paint via `app/utils/mapSearch.server.ts`, then `useMapSearch` + `/api/v1`); client-only `app/components/map/MapView.tsx` (MapLibre). Map moves change only the query string, and `shouldRevalidate` skips loaders for that. MapLibre controls go through `controlPosition()`; the RTL lint rule also checks JSX `style` objects and map control/anchor positions.
- i18n: `getT(locale)` / `useT()` in `app/i18n`; plurals are nested objects keyed by `Intl.PluralRules` category (`zero/one/two/few/many/other`), `other` required.
- Theme: cookie `theme` (`light` default) read in the root loader; toggled via POST `/theme`. Brand files in `public/brand/`; site icons generated by `npm run icons`.

## How to work

- Work one milestone from `docs/SPEC.md` §18 at a time. For anything larger than a small fix, propose a short plan and wait for approval.

## Non-negotiable rules
1. **Phone and contact privacy:** the lister's real phone (`owner_phone_encrypted`) is returned only by `GET /api/v1/backoffice/listings/:id/contact`, to the super_admin or to the supervisor whose scope contains the listing — every view audited. **Buyers' contact details** (enquiries, viewings, offers) are visible only to the supervisor in scope and the super_admin; listers never receive them, and buyers never receive the lister's. The public contact is the assigned supervisor's work mobile (SPEC §8). None of these ever go into public API responses, React Router loader data (it is serialized into HTML) outside the back-office views, client state, localStorage, or logs. Public serializers use explicit field allow-lists — never spread DB rows.
2. **Location privacy:** public code reads `display_point` only. Every public listing is an approximate area (no owner choice; the database only accepts `approximate`). The approximate offset is computed once on save and stored, never per request. **Who sees the true `point`:** the listing's owner/agent in the editing flow, the supervisor whose scope contains the listing, and the super_admin — always `Cache-Control: private, no-store`, never in public loaders, public API responses or public pages. The supervisor shares the exact location and the `exact_only` address fields with a client only when a viewing is confirmed; the share is recorded on the appointment and audited, and the client sees it only on their own viewing page. Only `public` address fields are ever public; `exact_only` and `admin_only` fields are not, and **property identifiers (`property_identifiers`, e.g. land parcel or PACI numbers) are never public** — only the listing's owner/agent, the supervisor in scope and the super_admin see them (financiers [P2] for requests addressed to them). Never collect personal civil IDs. Same leak surfaces as rule 1. See SPEC §2.3–2.4, §4.3, §22.
3. **SQL:** parameterized only (Knex builder or `knex.raw` with bindings). PostGIS uses `geography` with SRID 4326; longitude comes first in coordinates.
4. **Listing status values** are exactly: `draft, pending, published, rejected, returned, reserved, sold, rented, archived` (`returned` = returned for changes). Workflows are fixed in code; every status change of any workflow entity is written to `status_history` with actor, time and reason (SPEC §26).
5. **Money:** `numeric(14,3)`; currency comes from the listing's country, never from user input. Format with the country's decimal count. Other currencies are a display conversion only, marked "≈", with no margin (SPEC §24).
6. **i18n:** no hard-coded user-facing strings — everything goes through `app/i18n/ar.json` and `en.json` (add both keys together). Bilingual content is stored as `*_ar` / `*_en` columns.
7. **RTL:** use logical Tailwind utilities (`ps-`, `pe-`, `ms-`, `me-`, `start-`, `end-`, `text-start`). Don't use `left`/`right`/`pl-`/`pr-`/`ml-`/`mr-` for layout. Check every new screen in both `/ar` and `/en`.
8. **Validation:** Zod on every API endpoint, loader input, and action; share schemas from `app/shared/schemas`.
9. **Secrets** only from `.env` (never commit it; keep `.env.example` current). Seed credentials are dev-only.
10. **Roles and scope:** roles are `super_admin`, `supervisor`, `agent`, `owner` (`financier` reserved for [P2]); there is no `admin` role. Supervisors see only data inside their geographic scope (`supervisor_scopes`, descendants included) — filter in services, never only in the UI; an out-of-scope id is a 404. Payments, waivers, downward final-price corrections, refunds and deal cancellations need super_admin confirmation/approval (SPEC §19).

## Conventions
- Components: PascalCase files; hooks `useX`; services in `server/services` hold business logic, and routes/loaders stay thin.
- Map state and filters live in URL search params (`useMapUrlState`), not only in component state.
- Light theme is the default; colours come from the Tailwind theme tokens defined from SPEC §14 (`app/app.css`), not ad-hoc hex values. Text in the brand or error colour uses `text-primary-text` / `text-error-text` (AA in dark mode); form-control borders use `border-muted`, not `border-border`. Fonts: IBM Plex Sans Arabic / IBM Plex Sans.
